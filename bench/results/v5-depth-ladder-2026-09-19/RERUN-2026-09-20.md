## The limit this run carries

**The plugin build differs from the one the 13-note rung ran on.** That rung ran at `7c67c66`; this runs at
`b2c4548`, which contains `f2b3256` — free check ids on the contractless path and the dispatch bound the single
path now reads.

Within each rung the comparison is still clean, because both arms of a rung run on one build. What the difference
touches is the **cross-rung reading**: "41.8 % at 193K, then X at 285K" spans two builds.

Two facts bound how much that matters, and both were recorded before this run:

- The fix only changes a cell where a worker's reply was discarded over a check id. **Neither 13-note cell hit
  that path** — both dispatched exactly one worker and recorded `accept`. So the defect cannot have moved their
  numbers.
- The direction is known: on a cell that does hit it, the old build pays for discarded work. The new build is
  therefore cheaper or equal for `jev_single`, never more expensive.

So the cross-rung comparison is stated with this note attached, and a single-build three-rung ladder would need
the 13-note rung re-run as well (≈ $9, not authorised here).
